# AI 驱动的全网购物导航：战略与可行性研究

**研究日期：** 2026-09-30  
**范围：** 中国淘客业务、淘宝/天猫及主要电商/内容平台公开接口、商品与 SKU 图谱、优惠后价格、AI Agent、短视频/直播入口。  
**资料原则：** 平台/API 事实优先引用官方文档或监管机构来源；公开页面只证明页面明确写出的能力，不推断具体商业准入、接口配额、归因窗口或数据再分发权。具体签约和账号控制台条件仍需申请后逐项确认。本文不是法律意见。

## 结论摘要

这个方向**有产品机会，但原始的“全网实时最低价 + 自动购买”承诺不可作为 MVP 定义**。更现实、可建立信任的定位是：

> **在用户明确的商品规格、地区、会员/新客资格和履约条件下，对已接入渠道提供有来源、有时间戳、可解释的购买决策与价格追踪。**

重要判断：

1. 真正的基础设施不是 LLM，而是可审计的商品身份、Offer、价格条件和数据许可层。SKU 错合或资格判断错误，会让所谓比价失去意义。
2. “全网”暗示完整覆盖、同一时点与同条件比较；平台开放接口通常按产品、权限和业务场景提供数据，公开 API 不等于全量商品库或任意抓取授权。
3. 淘客佣金和“按消费者最低到手价排序”可能冲突。若佣金影响排序，应显著披露；推荐理由与消费者价格排序应可审计，最好提供纯价格模式。
4. 淘宝优惠金额应由规则引擎计算，LLM 只负责需求澄清、规则解释和自然语言交互。不能确认的券、会员资格、凑单条件应显示为未计入，而非模型估算成确定价格。
5. 绑定账号不能视作平台提供任意读取订单、购物车、私有优惠和会员数据的授权。账号 OAuth/开放平台授权必须具体到平台、scope、用户同意、审核和用途。
6. MVP 建议聚焦一个标准化、低售后类目和两个有正式授权的数据源，做型号/链接核价、严格同款匹配、优惠拆解、更新时间、官方跳转和价格提醒；暂不自动付款、无人值守下单或自行绕过风控。

## 1. 淘客业务与商业模型

### 1.1 淘客价值链

常见 CPS 导购链路可抽象为：内容/选品获客 → 商品与活动数据接入 → 生成带归因参数的推广链接 → 用户跳转到平台成交 → 平台按有效订单规则核算推广收益。平台会决定哪些商品、推广方式、媒体身份、订单状态与佣金数据可用。退货、取消、违规流量、归因丢失等可能影响最终收入，具体结算规则必须按平台和推广计划确认。

阿里妈妈/淘宝联盟官方开发资料列出商品搜索/详情、推广链接转换、优惠券转链、淘口令、推广位等 API 类别；使用前需要联盟开发者身份、媒体备案和 appkey，权限按权限包区分，部分高级能力可能需要邀约或审核。该资料证明存在相关能力，不证明每个新应用均能获得所有接口或对应字段。来源：[阿里妈妈开发者文档](https://developer.alibaba.com/docs/doc.htm?articleId=118970&docType=1&source=search&treeId=713)、[淘宝联盟 API 目录](https://developer.alibaba.com/docs/api.htm?apiId=74172)。

### 1.2 佣金与“用户最低价”的冲突

若排序目标是消费者到手成本最低，系统可能优先非佣金商品；若排序目标是平台净收入，可能优先高佣金商品。二者并非天然一致。建议把以下量分开存储和展示：

- `consumer_total_cost`：商品金额 + 运费/必选费用 − 用户确定可享受的优惠。
- `affiliate_revenue_estimate`：预计佣金或补贴，带规则版本和不确定性，不伪装为消费者优惠。
- `commercial_influence`：是否有推广关系、付费展示、佣金或平台优先。

默认排序应先以精确 SKU 和资格条件过滤，再按可验证消费者成本排序；价格接近时才用履约、售后、商家质量等用户偏好。付费广告/赞助位与自然推荐分开呈现。若业务选择商业排序，不应把它描述为客观最低价。

收入可先以联盟 CPS 验证，但需要计入退货冲销、归因成功率、数据/API成本、推理与客服成本、价格提醒留存和获客成本。以后可验证付费价格监控、商家数据质量/价格监测服务和明确标识的推广位；不建议首发时同时做广告竞价、代购履约、会员订阅和金融业务。

### 1.3 “全网最低价”不适合作为首期承诺

消费者价格取决于地区、库存、会员等级、新客资格、优惠券领取状态、支付方式、满减凑单、运费、预售、赠品和时段。可见商品价不是最终结算价，开放 API 能返回活动信息也不代表知道用户实际资格。建议用“已接入渠道内、在以下条件下最近验证的报价”，同时显示渠道覆盖、更新时间、纳入/未纳入条件和跳转后价格可能变化。

### 账号绑定的产品边界

平台 OAuth 只能授予其授权页面列明的 scope。购物导航可优先提供无需平台账号的公开/联盟报价和用户主动分享链接；若需要个性化价格、订单追踪或购物车能力，按平台分别申请最小权限并清楚解释用途、保存时间、撤销和删除方式。不要要求用户提供平台密码，也不要把登录 Cookie 当作常规接入方式。没有开放接口时，可由用户在平台结算页自行确认价格。

## 3. 商品库与跨平台 SKU 图谱

### 3.1 数据模型

把“商品”与“报价”分离，避免把不同平台 listing 误合并：

- `CanonicalProduct`：品牌、系列、型号、基础实体。
- `Variant/SKU`：容量、颜色、尺寸、版本、包装数量、套装、代际、渠道版等具体规格。
- `Offer`：平台 listing、店铺、SKU 声明、价格、优惠、库存、发货地、配送、售后与推广关系。
- `Evidence`：字段来源、原始平台 ID/链接、观测时间、抓取/接口版本、地区、用户条件、置信度及许可状态。

关系至少区分 `exact_same_sku`、`variant_of`、`bundle_equivalent` 和 `similar_to`。只有强证据才可进入同款最低价比较；相似商品可以推荐，但必须明确标为相似而非同款。

### 3.2 匹配策略

匹配先做确定性属性约束（品牌、型号、关键规格、包装数量、版本、成色），再用文本/图像/向量召回候选，最后通过规则或人工校验决定精确匹配。embedding 相似不等于同款。严控翻新/二手、国行/海外版、单品/套装、赠品、容量/件数和保修差异。

主键优先保留每个平台自己的商品/SKU ID；跨平台 canonical ID 是带证据和版本的映射，不应覆盖原始 listing。低置信度结果宁可不比较。价格结论应保存当时使用的属性快照、证据和规则版本，支持争议复现。

### 3.3 数据获取策略

优先次序：正式开放 API/联盟 API → 商家或品牌授权 feed → 用户主动粘贴链接后在许可范围内解析 → 有授权的数据服务商。公开可访问不等于可以无限频率抓取、缓存、再分发或用于商业排名。每个平台应建立 source policy：许可范围、允许字段、刷新频率、TTL、地域、展示要求、删除流程、异常熔断和联系人。

## 4. 淘宝优惠与可验证到手价

### 4.1 价格计算不是语言模型任务

每个优惠以结构化规则表达，例如：

`scope`（店铺/商品/跨店）、`eligibility`（新客/会员/领取资格）、`threshold`、`discount`、`cap`、`stack_group`（互斥/可叠加组）、`priority`、`time_window`、`region/member/payment constraints`。

计算流水线：

1. 标准化商品 SKU、数量、商家、收货地和用户显式条件。
2. 只纳入平台 API 明确返回且用户确认可得的优惠；不确定资格单独标出。
3. 生成满足时间、门槛、作用范围和互斥关系的候选组合。
4. 确定性规则引擎计算组合金额；对满减凑单设置搜索上限和可解释清单。
5. 分项展示商品金额、优惠、运费/服务费、赠品差异和未计入项。
6. 用户跳转平台后以实际结算页为准；价格或库存过期则刷新或降级为参考价。

### 4.2 价格状态与文案

建议状态：`verified`（明确数据源/条件下最近验证）、`estimated`（条件不完整的估算）、`stale`（超过 SLA）、`unknown`（无法验证）。报价显示 `observed_at`、`last_verified_at`、`expires_at`、地区和资格条件。避免“全网最低”“实时保证”“已含全部优惠”等不可证明表述。

应分别跟踪价格变更延迟、跳转后价格不一致率、失效优惠误报率、库存误报率、到手价误差 P50/P90。没有可验证条件的优惠必须排除于“最低价”比较或显著标识未计入。

## 5. 短视频、直播与未来购物入口

### 5.1 内容聚合不是简单搬运

未来购物入口可能从主动搜索转向个人 Agent：用户说目标、预算、禁忌和期限；Agent 追问关键规格；在授权渠道检索，返回少量可比较报价、价格变化和可信内容证据；用户在平台完成购买。短视频/直播可作为“发现与解释”的来源，但视频里的口播价格、直播券、库存、主播佣金和实时活动都可能迅速失效。

建议先接平台允许的分享链接、官方商品卡/推广链接或授权内容数据；保存内容 URL、作者/账号、发布时间、提取时间、商品实体和条件。AI 摘要只能陈述可追溯片段，不把种草话术当成商品事实。未经授权不要下载、转播或重新托管平台内容；显示跳转前的目标平台和商业关系，避免静默跳转。

### 5.2 抖音/快手规则注意事项

抖音开放平台协议和授权文档要求按授权范围调用，并限制未经授权取数、干扰平台或在用户未触发/不知情时跳转到其他页面或应用。来源：[抖音开放平台协议](https://open.douyin.com/platform/resource/docs/operation-standard/agreement-protocol)、[抖音授权说明](https://open.douyin.com/platform/resource/docs/develop/permission/web/permission)。快手平台协议也对内容复制/分发、账号和第三方应用使用作出限制。来源：[快手平台协议](https://open.kuaishou.com/platform/protocol)。

短视频/直播场景的站外链接规则会随账号类型、产品形态、内容和平台政策变化；不能仅凭“某种外链可行”推断所有带货场景均允许。接入前逐一核验官方组件、账号资格、站内交易要求和跳转文案。

## 6. AI Agent 架构与安全边界

建议分层：

1. **交互与意图层**：把自然语言转成预算、型号、规格、地区、时间、偏好、不可接受条件；遇到关键缺项先澄清。
2. **商品检索层**：关键词/属性检索 + 语义召回 + 用户历史偏好；先硬过滤，再做排序。
3. **实体解析层**：canonical 商品、variant、平台 offer、相似候选与证据。
4. **价格与优惠引擎**：确定性规则、金额运算和组合约束；LLM 不直接决定金额。
5. **推荐与解释层**：解释理由必须引用结构化事实；佣金影响独立记录。
6. **工具与交易层**：平台适配器、域名 allowlist、schema 验证、权限检查、预算/频率限制、幂等键和审计日志。
7. **信任与运营层**：价格过期、投诉/下架、人工复核、供应商策略、纠错和隐私删除。

商品标题、评论、直播弹幕与用户提供链接都是不可信输入，不能让它们覆盖系统指令或触发任意工具。初期 Agent 只读检索和解释；官方跳转由用户明确点击。任何地址、加入购物车、订单提交、取消、售后或支付动作都应展示参数和影响并要求用户确认。MVP 不保存支付密码，不绕过验证码、频控或平台安全机制。

## 7. 隐私与监管边界

中国《个人信息保护法》是个人信息处理的主要法律框架，要求处理个人信息有合法基础，并对自动化决策、个人权利等作出规范。来源：[工业和信息化部转载的《个人信息保护法》全文](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)。

《网络数据安全管理条例》规定网络数据处理者的安全与个人信息保护责任，并禁止窃取或以其他非法方式获取、出售或非法提供网络数据；自动化收集个人信息应关注必要性与合法性。来源：[司法部法规文本](https://xzfg.moj.gov.cn/front/law/detail?LawID=1734)。国家网信办关于自动化收集的说明也强调不得妨碍网站正常运行，但不构成对所有第三方商业抓取的普遍授权。来源：[国家网信办说明](https://www.cac.gov.cn/2019-06/16/c_1124630015.htm)。

落地要求：数据最小化、用途告知、明确授权和撤销、删除/导出入口、敏感数据不进模型日志、密钥隔离、权限审计与事件响应。对个性化推荐和佣金披露，应提供透明理由和不依赖个性化的使用路径，并由中国执业律师按产品真实形态核验法律义务。公开网页、robots.txt 或技术上能访问都不单独构成平台许可。

## 8. 产品设计建议：年轻化但以信任为先

面向年轻人的“前卫”不应等于让 AI 全自动替用户付款，而应表现为自然语言入口、跨内容发现、个性化但可控、结果透明、快速完成任务。首页直接进入可用流程：粘贴商品链接/输入型号/描述需求；之后确认规格和地区，展示报价比较与价格追踪，而不是长篇教育型 landing page。

推荐卡片至少显示：同款/变体/相似标签、规格、到手价明细、未计入优惠、店铺/履约/售后、更新时间、数据来源、佣金/广告披露和官方跳转。提供“最低可验证价”“综合推荐”“不看推广”等排序切换；避免暗中把高佣金商品伪装成最优。

行为个性化需可解释、可编辑、可清除：预算区间、品牌偏好、耐用/速度/售后权重、购买历史信号（需明确授权）、不喜欢的广告类型。不得把推断偏好当作用户明确承诺，也不应用行为画像劣化不同用户的基础价格公平性。

## 9. MVP、路线图与验证

### 阶段 0：可行性验证（2–4 周）

选一个低售后、标准化类目（如有清晰型号的数码配件或家清耗材），选两个可正式授权的数据源。建立 API/条款矩阵、Offer/Variant/Evidence schema、手工金标准集（建议先从数十到数百个 SKU/任务开始）、价格条件和归因测试方案。提交真实接入申请，验证字段、缓存与再展示许可、刷新成功率和跳转归因。

### 阶段 1：MVP（约 4–10 周，依授权进度调整）

自然语言/链接/型号输入 → 规格澄清 → 限定渠道候选 → exact/variant/similar 分类 → 确定性价格拆解 → 更新时间和来源 → 官方平台跳转 → 收藏/降价提醒。提供人工纠错与审核台。仅支持商品和资格明确的数据。

### 阶段 2：受控扩展

扩展至 3–5 个正式授权渠道和少量标准化类目；增加用户条件化报价、价格历史、结算前刷新、内容分享解析和更强的优惠规则引擎。用真实点击、结算确认、订单归因与客服数据校准，而非只以离线搜索指标判断成功。

### 阶段 3：平台化能力

在平台明确许可且用户授权的前提下，评估购物车/订单草稿等受控操作；发展品牌/商家 feed、数据纠错、B2B 价格监测和多收入模型。价格保障、代购履约或自动支付需单独评估资金、售后、消费者责任、风控和客服体系，不属于导购 MVP 的自然扩展。

### 指标

- **北极星：**每周有证据的购买决策数：用户指定了明确 SKU/条件、看到至少两个有来源和时间戳的报价及条件，并完成官方跳转、收藏或设置提醒之一。
- **数据质量：**exact-match precision、错误合并率、false-cheapest rate、价格刷新成功率、价格误差 P50/P90、优惠合法组合率、库存误报率。
- **产品：**需求澄清后有效候选率、任务完成时间、官方跳转率、结算确认率、纠错率、7 日/30 日复用、提醒打开与转化。
- **商业：**跳转到有效订单转化、归因成功率、退货冲销后每个决策贡献毛利、CAC/LTV、数据/API/模型/客服成本占比、平台集中度。
- **信任：**过期价格投诉、跳转价格差异、未披露推广展示率、佣金排序影响率、数据删除时延、越权工具调用拦截率。

建议设定发布门槛而非一开始承诺通用行业数字：进入“同款最低价”结论的匹配精度要由人工金标准与具体类目损失分析决定；SKU 错合率、价格 P90 误差或优惠误报超过阈值即降级展示/停止扩类。若平台授权或归因无法稳定获取、净贡献毛利持续为负，则停止该渠道或调整商业模型。

## 10. Go / No-Go 清单

1. 是否取得至少一个平台对商品字段、缓存、商业展示、推广跳转和订单归因的书面/控制台许可？没有则不能把该平台计入覆盖承诺。
2. 是否能建立可审计的 exact SKU 金标准，并解释包装、版本、数量、成色和赠品差异？不能则仅提供相似推荐，不宣称同款最低价。
3. 是否能计算指定用户条件下的到手价，且明确哪些券和费用未纳入？不能则称参考价，不称可得价。
4. 用户不绑定任何平台账号时，核心比价是否仍可用？若否，先重新设计授权价值和最小权限。
5. 佣金、赞助位是否与纯价格排序隔离并有清晰披露？若否，不应宣称中立或最低价。
6. 数据源失败、价格过期、商品下架或平台撤权时，是否有熔断、降级、删除和未覆盖状态？
7. 是否验证“已验证购买决策”带来的净毛利、复购或提醒留存，而不只是点击？
8. 若短视频/直播内容无法授权或稳定获取，核心体验是否仍成立？

**最终建议：**先立项“可信的跨平台商品决策与价格追踪”，不要先立项“全网爬虫/全品类自动购物”。最早的护城河是高精度 SKU 身份、用户条件下可复现的价格证据、合规数据源和稳定归因；Agent 是将这些能力变成更自然入口的交互层。
